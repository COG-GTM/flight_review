# Flight Review — SBOM package for AO / ISSM review

Software Bill of Materials for the Flight Review web application
(`COG-GTM/flight_review`, PX4 ULog upload / analysis / plotting), produced to
support an RMF authorization decision. Everything in this directory is
regenerated by `generate_sbom.sh` from a checked-out commit; nothing is hand
edited except the `docs/` narratives and the browser-runtime component list in
`tools/browser_runtime_bom.py`.

## Reading order

| # | File | Audience | Purpose |
|---|------|----------|---------|
| 1 | `docs/01_Transmittal_Memo_AO_ISSM.md` | AO, ISSM | What was scanned, boundary, headline results, known limitations, requested decisions |
| 2 | `docs/02_RMF_Control_Mapping.md` | ISSM, ISSO, assessor | How this package satisfies / supports NIST SP 800-53 Rev 5 controls and the SP 800-37 Rev 2 RMF steps |
| 3 | `docs/03_NTIA_Minimum_Elements_Attestation.md` | ISSM, assessor | Element-by-element attestation against the NTIA *Minimum Elements for an SBOM* (EO 14028 §4(e)) |
| 4 | `docs/04_Vulnerability_Disposition.md` | ISSM, system owner | Deployment-context analysis of the grype findings, POA&M candidates, VEX hand-off |
| 5 | `vulnerability/SUMMARY.md` | ISSM, ISSO | Generated severity × fix-state matrices and Critical/High tables per artifact |
| 6 | `inventory/COMPONENT_INVENTORY.md` | anyone | Human-readable component tables (name, version, license, supplier, purl) |
| 7 | `GENERATION_RECORD.md` | assessor | Tool versions, commit, image digests, artifact hashes — reproducibility record |

## Regenerating

```
cd ~/flight_review
./sbom/generate_sbom.sh                # builds images with docker-compose.prod.yml, then scans
SKIP_BUILD=1 ./sbom/generate_sbom.sh   # reuse already-built images
python3 sbom/tools/render_pdf.py --out sbom/dist/Flight_Review_SBOM_Package.pdf   # optional PDF bundle
```

Requires docker (compose v2), [syft](https://github.com/anchore/syft),
[grype](https://github.com/anchore/grype), jq, python3, git. `render_pdf.py`
additionally needs the `markdown` Python package and `wkhtmltopdf`.

Regenerate on every release candidate and whenever a base image or
`app/requirements.txt` changes; commit the result alongside the change so the
SBOM in `main` always describes `main` (CM-8(2), CA-7).

## Scope notes

* Images are built from the Dockerfiles in this repository at the recorded
  commit. `ubuntu:noble`, `nginx:latest` and `certbot/certbot:latest` are
  **unpinned** tags; the exact base digests used are in
  `GENERATION_RECORD.md`. A rebuild on another day can legitimately differ.
* `app/requirements.txt` pins only `bokeh`; the other 124 Python packages are
  whatever pip resolved at build time. The SBOM records the resolved versions.
* The app image also contains `jupyter` and `pylint` (declared in
  `requirements.txt`) and their ~100 transitive dependencies. They are not
  needed at runtime and are called out in the disposition document.
* The browser-runtime BOM is derived from the Jinja templates by hand; it is
  the only artifact not produced by an automated cataloger.
* Nothing in `data/`, `app/private_key/`, or `letsencrypt/` (runtime data,
  keys, certificates) is read or recorded.
